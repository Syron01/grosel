Optimisation as a constrained decision problem

Every run is a plan; every plan is a resource and quality vector. This layer builds a Pareto frontier from measured plans and solves for the best one under a VRAM budget, a time limit and a quality floor. The target is not a new model — it is a model-independent decision core.

01 Definition

S = (q, k, c, o)             resolution, steps, cache state, decode offload
R(S) = (M(S), T(S))          peak VRAM (GB), end-to-end time (s)
Q(S) = (P_native, A_clip)     native megapixels, CLIP prompt alignment
F(B, T_max, P_min) = { S | M(S) ≤ B,  T(S) ≤ T_max,  P_native(S) ≥ P_min }

S* = argmaxS∈F P_native(S)     (quality)
     argminS∈F T(S)            (speed)
     argminS∈F M(S)            (memory)

λ_B = ΔQ*/ΔB,  λ_T = ΔQ*/ΔT   shadow price: what loosening a constraint buys
I1 Dominance: if a plan is faster, lighter and better at once, the old plan is dropped.
I2 Measurement first: plans come from real telemetry; prediction is only used for unmeasured configurations.
I3 Shadow price: zero means loosening the constraint buys nothing, not that it is inactive.
I4 Generality: the same schema applies to text and audio models; only the quality metric changes.

Quality here is two measurable components: native draw resolution and CLIP alignment. Aesthetics, anatomy and hand quality do not fit CLIP, so a human-evaluation layer stays on the roadmap.

04 Model-agnostic streaming

The same plan schema ignores model architecture and looks only at the largest indivisible block. A block group moves to the GPU and returns to CPU when its work is done. If one block fits the budget, total model weight may exceed it. Qwen-Image 2.1 reached a 1.36 GB phase peak from a 31.7 GB checkpoint.

M_phase = max(M_enc, M_den, M_dec)      phase peak model, VAE excluded
M_den = g · w_block + A(S)            denoise: group + activation
M_enc = w_emb + w_layer + A(T)        encode: embedding + single layer
lm_head ∉ M_enc : diffusion reads hidden state only

w_max + A + V ≤ B        streaming feasibility (block, activation, VAE workspace)
T_den ≈ step · (k · S + W / BW)   PCIe + compute floor
g* = max{ g : g · w_block + A + V ≤ B }   group length plan

Where residency, quantisation and cache separate

Grosel is not a new image model. It is a conversion and scheduling layer that runs an existing model inside a given VRAM budget. Every value on this page is read from the live engine.

01 System

One pipeline runs a diffusion transformer, a text encoder and a VAE on a single 8 GB card. Fast mode uses FLUX.2 Klein (FP8); quality mode uses Qwen-Image 2.1 (FP8 transformer + NF4 text encoder), streamed by phase. Conversion is three separate decisions:

02 Cost model

Generation time is encode + denoise + decode. Swapping happens only at the encode boundary; on a cache hit the encode term falls to zero.

B   = — GB      budget left with the transformer resident
Sₜ  = — GB      transformer GPU copy
S_e = — GB      text encoder GPU copy
R   = 0.90 GB    safety margin

dual ⇔ B ≥ S_e + R

E2E = (1 − h)·(E_enc + s·E_swap) + Σ E_step + E_dec
h = cache hit (0 or 1) · s = swaps per prompt (0 or 2)

I2 Same prompt + new seed ⇒ h = 1, encode cost zero.

03 Residency rule

The planner reads module sizes and the budget, then groups all swaps into a single boundary before denoise starts. Step times stay flat and the VRAM peak stays predictable.

if B ≥ S_e + R:
    transformer ← GPU ; text_encoder ← GPU      # dual resident
else:
    text_encoder ← GPU ; transformer ← pinned RAM
    encode(prompt)
    transformer ← GPU ; text_encoder ← pinned RAM

key = sha1(final_prompt)
if key in cache: h = 1 else: h = 0

The cache key is the compiled prompt, so changing style or physics anchor changes it. The seed is not part of the key: the same scene with a new seed pays no encode cost.

The general case is a shortest-path problem over the module sets held at each phase boundary, where the transition cost is swap time:

C_t(S) = min_{S'} [ C_{t-1}(S') + swap(S', S) ] + compute_t(S)
subject to:  bytes(S) ≤ B
C_0(∅) = 0 ,  objective: min_S C_T(S)

On a two-module linear pipeline this DP reduces to the single rule above. Multi-model pipelines (text prefill/decode + image denoise) use the full form; today's implementation is the two-module special case.

05 Limits today

  • The drawing grid comes from the ceiling, not the tier name. Peak scales with the grid (fitted here: 602 MB per megapixel over measured 0.46 / 0.92 / 2.06 MP draws), so 1080p is a 1680×944 draw finished by bicubic to 1920×1080 — warm 4.84 GB, cold 4.92 GB, inside the 5.0 GB promise. Uncapped it drew 1920×1072 and measured 5.12 GB; measured structural detail was the same either way (3754 vs 3732).
  • On an 8 GB card 2K and 4K are resamples, not more compute. The same fitted cap gives all three tiers the same 1680×944 grid; the panel prints native → target so the difference is visible instead of advertised.
  • One second only at 420p warm. 640×368 skips decode offload: 3 steps + cache measured ≈1.1 s. Not true at 1080p.
  • Hand quality is the model's own limit. The anatomy anchor now attaches only to prompts that contain people. The larger base grid is more consistent, but 6 steps do not fix hands.
  • 1.1 GB only in classic mode. BF16 + CPU flow produces 720p in 10.4 s; the speed/memory trade is real.
  • More steps are not more quality. At the same seed, 6 steps drew worse hands than 4; the model is distilled for 4. CRPF is experimental and off by default.
  • BF16 full residency does not fit 8 GB. Weights alone are —, so conversion is mandatory, not optional.
